# 秘密花园生日网站：Codex 开发计划（A 方案）

版本：2.0 · 2026-10-28。用户已选择 A「走进秘密花园」。本版替代早期手机卡片式界面与写实夜间建筑方向；固定谜题和音乐赠礼规则保持一致。

目标是做一座明亮、柔软、有个人气息的可探索花园：桌面用于第一次现场共同探索，手机便于以后随时回来点歌。花园总览中可以看见信号花圃、音乐花圃和礼物小门，点击物件后视角靠近，完成互动再返回同一花园。

本包是开发计划、实现规格和内容模板，尚不包含已经实现的网站、最终美术素材或通过验证的网页。下面的验收项都是实施时要执行的要求。

## 今天怎样在 Codex 开始

1. 在 Codex 中打开网站项目目录；新项目也可以从一个空目录开始。已有代码先保留，沿用其规范和技术栈。
2. 把整个 `birthday-site-handoff/` 文件夹放在项目根目录。本包不是 npm 项目，不要在交接文件夹里初始化应用。
3. 将你认可的图片、视频放到项目的 `reference/` 目录，供开发对照。参考截图只用于理解风格，不直接当作公开网站的美术资产。没有原文件也可以依据本包的具体视觉描述开始。
4. 把 `CODEX_PROMPT.txt` 全文发给 Codex。本轮指令明确执行 M0＋M1，交付可以操作的美术样片；先检查画面与动态，再接完整业务。
5. 样片之后，按 `docs/DEVELOPMENT_PLAN.md` 中 M2—M5 的阶段指令继续。日常实现选择可由 Codex 自行决定。
6. 把九首真实曲目、礼物和个性化文字填到实现项目唯一的内容配置中；阶段交付时列出尚未填写的项目。

M1 的成果应该是你能打开并亲手操作的花园：看见层次、碰一下花、靠近一个地方，再返回总览。几何占位、静态概念图和一份设计介绍都不等于美术样片通过。

## 已确认的视觉方向

- 鲜活苔藓绿、淡蓝天空、花瓣粉、奶油白和少量暖光；圆润的地形、柔软的花叶、手绘细节与局部手写字。
- 近景花叶、中景小路和物件、远景草丘与天空构成层次；环境有轻微风，点击有明确反馈。
- 总览 → 点击物件靠近 → 内容互动 → 返回总览。主要场景固定为 `overview / puzzle / music / lock / gift`。
- 以有限 2.5D 分层场景和少量关键立体物件实现空间感。谜题数字、曲目、正文和按钮始终使用真正可读、可操作的 HTML。
- 不把整屏答案或交互按钮画进一张背景图。参考作品的专有角色、名字、城市回忆与素材不会自动成为本项目内容。

## 六个里程碑

| 阶段 | 完成后的具体成果 |
| --- | --- |
| M0 项目与素材准备 | 明确运行方式、现有栈、参考方向、资产清单和真实素材缺口 |
| M1 可操作美术样片 | 完整花园总览、花的回应、一个靠近/返回动作、可用的基础降级 |
| M2 场景与信号谜题 | 三处入口和路线、完整 XOR 操作、两段答案、0305 密码卡 |
| M3 音乐花圃 | 九首固定曲目、独立随机抽取、落花反馈、复制和随时回访 |
| M4 礼物与个性化内容 | 输入 0305 开门、实物礼物揭晓、生日含义、真实文案与素材 |
| M5 彩排与交付 | 现场设备和手机检查、性能调整、兼容降级、构建与部署说明 |

每阶段先产出可观察结果，再按相应标准检查。视觉方向有明确反馈时，先在 M1 修正，不把主画面的审美问题积累到全功能完成以后。

## 已经确定的产品规则

- 四位密码仅为字符串 `0305`，是送礼者的生日；这层含义只在开门后揭晓。
- 解码片 `1001`；A 信号 `1010` → XOR 输出 `0011` → 3 → `03`；B 信号 `1100` → `0101` → 5 → `05`。两段按顺序拼成 `0305`。
- 输出灯初始为空，先由参与者逐位填 0/1 并检查，再输入十进制结果。提示、引导完成都属于正常玩法，没有惩罚或倒计时。
- 解码片 `1001` 读为 9，可用来引出九首曲子；不要把解码片和最终密码卡混称。
- 曲目固定编号 1—9。每次独立等概率、有放回地抽取，允许连续抽到同一首；刷新和回访本身不重抽。
- 抽到的曲目由收礼人自行复制/发送给送礼者，再约定现场演奏或视频。网站不会自动发送消息。
- 音乐可以直接进入，不要求先做题；抽歌不是打开礼物的前置条件。记得密码的新设备可以直接开门。
- 开门仅设置 `giftUnlocked`，不会伪造 `puzzleSolved`；“我的密码卡”只在当前设备已完成谜题时显示。
- 首次现场体验由你们控制节奏；以后回来点歌可以直达。音频主动开启，减少动态效果和 WebGL 失败都保留核心功能。

## 默认实现方案

已有项目优先沿用原栈。空项目采用 React + TypeScript + Vite，场景以 Three.js / React Three Fiber 组织，GSAP 负责统一视角转场，HTML/CSS 负责文字和表单。分层插画可以作为场景中的图层，不要求先制作完整 3D 世界或学习建模。

选择相互兼容的稳定依赖并保留锁文件。环境动作、相机动画和用户操作状态要有清楚的责任划分，具体见技术规格。美术工具或图片生成不可用时，先完成可实现部分并明确素材缺口；不能用不存在的资源路径、空白图或粗糙占位冒充最终美术。

第一版以纯前端静态应用完成，不需要账号、数据库或管理后台。仅保存必要进度与最近一次抽歌。初次搭建不自动部署；M5 提供构建和部署步骤，发布平台与访问范围由用户后续明确。

## 你需要准备的真实内容

| 内容 | 是否影响开始开发 | 正式展示前的要求 |
| --- | --- | --- |
| 对方称呼和你的署名 | 不影响 | 可填写，也可保持“你”并隐藏署名 |
| 九首曲名 | 不影响 M1/M2 | 必须替换九个占位标题，保持编号与曲目对应稳定 |
| 每首曲子的理由 | 不影响 | 可各写一句真实原因，也可留空 |
| 礼物名称与介绍 | 不影响 M1—M3 | 正式开门后必须展示真实内容 |
| 礼物照片 | 不影响 | 有照片则使用，没有则保留原创礼物图形与真实文字 |
| 开场语音或短音效 | 不影响 | 可选；无素材时不显示失效播放器 |
| 花园美术素材 | 不影响项目初始化 | 是 M1 视觉验收关键，需要制作或准备相互一致的资产 |

`content.template.json` 的空素材路径为 `null`，表示尚未提供。开发时可以复制/转换为 `src/config/content.ts` 等唯一内容来源，但不要维护两份会漂移的运行时配置。`placeholder: true` 用来识别尚未填入的曲目和礼物，交付时必须如实报告。

## 验证与交付说明

本包已经核对需求一致性与谜题计算；没有运行网站，也没有把未来验收项写成通过。后续 Codex 应记录真实执行的构建、逻辑检查、浏览器检查及目标设备彩排结果。

网页四位密码是礼物揭晓机关，纯前端资源可被检查；它不提供真实身份认证。这项说明仅供开发，不进入收礼人的体验文案。
