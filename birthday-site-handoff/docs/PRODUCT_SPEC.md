# 梦幻音乐花园 A：产品、交互与文案规格

> 本文件是待开发的产品规格，不表示网站已经实现、上线或通过浏览器测试。用户已经选择 A「走进秘密花园」；本版替换此前偏写实夜景及普通卡片式页面的视觉组织。开发阶段与交付方式见 `DEVELOPMENT_PLAN.md`。

## 1. 目标与已经确定的约定

这是一个送给特定收礼人的生日礼物网站。它是一座明亮、柔软、有前后层次的小花园：两个人现场一起打开，靠近物件、解读信号、抽到一首未来可以请送礼者演奏的曲子，最后用密码打开礼物之门。实物礼物在线下交付。

优先照顾两个场景：

- **第一次：电脑现场共同探索。** 大画面有观赏价值，关键动作由人主动触发，能随时停下来聊天、猜题、看结果。没有计时、催促或自动跳到下一章。
- **以后：手机或电脑直接点歌。** 不必重新解题，也不受设备已有进度限制。最近抽到的曲目卡容易找、容易读、容易手动发给送礼者。

固定约定如下：

| 项目 | 规定 |
| --- | --- |
| 主方向 | A「走进秘密花园」；总览、点击靠近、返回同一花园 |
| 礼物密码 | 四位文本 `0305`，保留前导零 |
| 数字含义 | 送礼者的生日；仅在礼物成功解锁后揭示 |
| 第一关机制 | 同一张解码片与 A、B 两张信号卡分别逐位比较 |
| 解码片 | `1001` |
| A 卡 | `1010` → 异或输出 `0011` → 十进制 3 → 保存为 `03` |
| B 卡 | `1100` → 异或输出 `0101` → 十进制 5 → 保存为 `05` |
| 密码形成 | 按 A、B 顺序拼接 `03` 与 `05` |
| 音乐过渡 | 解码片 `1001` 也可读成十进制 9，引出九首曲子 |
| 抽歌规则 | 每次独立、等权、有放回地随机选编号 1—9，允许连续重复 |
| 曲目映射 | 一个固定编号始终对应同一首已配置曲目 |
| 礼物交付 | 网页揭晓，送礼者随后在线下交付实物 |

文案不预设双方的恋爱关系，不虚构共同经历、称呼、喜好、曲名、乐器或礼物种类。不添加其他日期或第二套密码。

## 2. 同一个花园里的五种视图

主体验采用持续的花园舞台。近景可以用 DOM 阅读层承载题面和卡片，但环境、构图和空间过渡应保持关联。首屏可以看见远处音乐花圃和小门的轮廓，不把未来内容完全藏成几个抽象按钮。

| 视图语义 | 工程场景名 | 收礼人做什么 |
| --- | --- | --- |
| 邀请与花园总览 | `overview` | 初次在花园背景前接受邀请；然后选择一个地方靠近，也可直接点歌 |
| 信号花圃 | `puzzle` | 操作四盏灯，先完成 A，再完成 B，取得密码卡 |
| 音乐花圃 | `music` | 主动抽一首、查看最近结果、复制点歌文字 |
| 礼物之门 | `lock` | 输入记得的四位密码，或回去寻找线索 |
| 门内礼物 | `gift` | 看礼物、读短文字、理解密码含义 |

`1001 → 9` 是谜题完成后的短过场，不需要建立独立世界或强制的新题目。邀请属于 `overview` 的临时引导层，共用同一环境，只改变文案和视角；不要制作两套重复的首页。

首次推荐路线为：邀请 → 总览 → 信号花圃 → 密码卡与短过场 → 音乐花圃 → 礼物之门 → 礼物。路线是引导，音乐始终有直接入口，抽歌也不是开门的前置条件。

所有近景有明确的「回到花园」入口。画面里的物件入口必须有可点击、可聚焦的等价操作；手机不依赖悬停，关键入口不要求精准拖动才能发现。第一次进入可用一条短提示引向信号花圃，但不自动替访客点击。

## 3. 邀请与总览

### 3.1 可直接使用的示例文案

暂定标题：

> 留给你的一小片世界

邀请：

> 这里藏了一点东西。  
> 陪我进去看看？

主入口：

> 走进去看看

常驻的次级入口：

> 我来点歌

总览中的短提示：

> 路边有两段信号，等你读懂。

三个地标名称：

- 信号花圃；
- 音乐花圃；
- 礼物之门。

这些是场景提示和可访问名称，是否常驻显示由视觉规格决定。无需在总览上方放一排占据画面的导航卡片。

### 3.2 行为

- 全新访问从邀请开始。点击主入口后，花叶轻轻让开、视角进入总览；随后由访客主动进入信号花圃。
- 首屏不主动展示密码、生日含义或九首数量。远处可以看见花圃轮廓；主动进入音乐花圃后正常说明九首。
- 首访、回访、新设备都能直接点歌。此入口只切换视图，不取得密码、不设置谜题完成、不解锁礼物。
- 可选的私人语音和环境声音必须主动开启；未提供音频时不显示空播放器。
- 不用虚假的长加载过程营造气氛。资源未准备好时给出真实、短的加载状态；可用内容先展示。
- 没有称呼时使用“你”，没有署名时省略。不得从账户信息推断收礼人的名字。

## 4. 第一处：信号花圃

### 4.1 场景与题面

四个透明的小灯是可操作的输出位；解码片和信号卡可以有纸片、玻璃片的外观。具体的 `0 / 1`、题目说明和按钮由真实文字与控件绘制，不能烘焙进背景图。

标题：

> 两段等待被读懂的信号

规则：

> 把信号卡和解码片按位置比较：  
> **相同，记作 0；不同，记作 1。**  
> 0 是熄灭，1 是亮起。

此时不解释 `1001` 代表 9，也不出现“生日”“日期”“3 月 5 日”等提示。

### 4.2 每张卡的布局与初始状态

每次集中显示当前一张卡，四个位置从左到右对齐：

1. 解码片；
2. 当前信号卡；
3. 我的结果。

下表是开发答案，不是初始界面的答案表：

| 行 | A 段 | B 段 |
| --- | --- | --- |
| 解码片 | `1001` | `1001` |
| 信号卡 | `1010` | `1100` |
| 正确输出 | `0011` | `0101` |

“我的结果”四格初始全部为 `null`，显示短横线或问号。访客每格选择 `0 / 1`；亮灭是辅助，数字始终可读。不能把尚未选择画成已选择的 0，不能预填正确输出。继续已有有效进度时恢复选择。

### 4.3 第一步：比较四个位置

四格都选过以后启用：

> 检查这段信号

未填完：

> 还有信号等待选择。

有误：

> 还有位置没对上。试着从左到右，再比较一次。

不扣分、不清空、不限次数。普通校验不给出所有正确答案；帮助由访客主动展开。四位都正确后，固定当前输出，进入读数字步骤。

### 4.4 第二步：读成十进制数字

四盏输出灯下，从左到右显示位权 `8、4、2、1`。

题目：

> 把亮灯下的数字加起来，这段信号表示多少？

输入说明：

> 填写数字，答案会自动保存成两位。

输入框默认空白，不能用占位文字泄露答案。A 接受 `3` 或 `03`，B 接受 `5` 或 `05`；它们是十进制输入，不要求填写二进制串。

确认按钮：

> 确认这个数字

错误提示：

> 只把亮灯下的数字加起来，再试一次。

成功后 A 统一保存 `03`，B 统一保存 `05`。A 完成时显示「第一段，读懂了」和「继续读下一段」。B 完成后，将两张结果卡按顺序合在一起：`03 ｜ 05` → `0305`。这里是文本拼接，不能显示为相加得到 8。

### 4.5 三级提示

入口「给我一点提示」持续可见，每次按需展开：

| 级别 | 行为 |
| --- | --- |
| 一级 | 引导只看当前卡最左边一格，判断两个输入是否相同 |
| 二级 | 演示最左边两个 1：相同，所以输出 0；可展开四种组合的规则 |
| 三级 | 「带我完成这一段」；主动选择后演示当前卡四位输出、位权求和及十进制结果 |

完整示范后点击「我读懂了」，本段按正常完成记录。要同时记录该段的正确输出、十进制结果和两位片段，不能只把总完成标记设为 true。帮助不减少礼物内容，没有失败标记。

两张卡完成后，可显示一句：

> 刚才用到的规则，在计算机里叫“异或”。

不再增加长篇必读课程。

## 5. 密码卡与通往音乐的短过场

### 5.1 收好密码

标题：

> 这四个数字，留到最后

正文：

> 先把它收好。  
> 花园深处的那扇门，会用到它。

卡片显示 `0305`，按钮「收好密码」。此时不解释送礼者生日。

之后提供小型入口「我的密码卡」，**严格只在 `puzzleSolved === true` 时出现或可用**。仅访问音乐、记得密码或已经解锁礼物，都不能反推谜题完成。

### 5.2 解码片的另一个读法

将刚才的 `1001` 与位权 `8、4、2、1` 对齐，突出首尾两位，显示 `8＋1＝9`。

文案：

> 这张解码片，还有另一个读法：9。  
> 接下来，是九首我想弹给你听的曲子。

按钮：

> 去音乐花圃

可以让光线沿路径延伸，或九朵花依次轻轻亮起。这是短解释，访客可以直接继续；减少动态效果时展示最终静态状态。生日含义仍保留在门内。

`1001` 始终叫“解码片”；`0305` 始终叫“四位密码”或“密码卡”，避免把两种道具都叫钥匙。

## 6. 第二处：音乐花圃

### 6.1 场景与入口

这里有九朵持续存在的音乐花，每朵绑定一个固定曲目编号。等待时随共同的风轻轻摆动，靠近时给予小幅回应。抽取由一个清晰的主操作触发：可以是中央种子及其等价按钮。

标题：

> 想听的时候，就来抽一首

正文：

> 这里有九首我想弹给你听的曲子。  
> 今天可以抽，以后的某一天想听了，也可以再来。

规则：

> 每次都从九首里随机抽取，可能再次遇到同一首。

抽取按钮：

> 让花园替你选一首

次级入口：

> 先去看礼物

已解锁时可改为「重看礼物」。点击装饰花可以产生回应，但不能偷偷变成定向选歌或另一种随机规则。

### 6.2 一次抽取的产品契约

1. 访客主动点击抽取。
2. 立即独立、等权地选定一个编号，记录本次结果并尝试保存。
3. 暂时阻止重复点击，播放种子飘向所选花朵、花展开的短动画。
4. 显示刚才已经确定的结果卡。

每次都在完整的九首中抽取，允许连续抽到同一首。不重排编号与曲名，不为了“看起来更随机”排除重复。

打开页面、刷新、重新渲染、返回花园、播放动画本身都不能重新抽取。最近一次结果保留，刷新恢复时直接显示这张卡，不再播一段让人误以为重抽的随机过程。

低性能、减少动态效果、动画中断或存储不可用，都不能丢掉本次已确定结果或让抽取一直锁定。具体容错由技术规格实现。

花始终留在花圃里。无每日限次、过期、库存、兑换额度、集齐任务或核销。抽歌不是看礼物的前置条件，v1 不做曲目历史画廊。

### 6.3 曲目卡与发送约定

卡片包括：

| 内容 | 规则 |
| --- | --- |
| 编号 | 两位显示，例如 `07` |
| 曲名 | 配置中的真实曲名 |
| 选择理由 | 配置中的真实一句话，为空就省略 |
| 邀请 | 下面的通用说明 |

邀请：

> 想听的时候，把这张卡发给我。  
> 可以录给你，也可以找一天当面弹。

按钮「复制点歌文字」，复制内容模板为：

> 我抽到了 07 号《曲名》。有空的时候，想听你弹这一首。

编号和曲名来自当前结果，不复制示例字样。成功后显示「已复制，可以发给我了」。失败时展示同一段可选择的文字，并提示手动复制。手机上卡片容易截图，正文不被花朵、光点或按钮覆盖。

由收礼人自行发送。网站不显示“已发送”“已通知”“对方已收到”，不自动打开聊天工具，也不承诺送礼者立即演奏。v1 不要求制作在线演奏播放器或下载卡片功能。

## 7. 第三处：礼物之门

这扇门在总览里就有轮廓；靠近以后，四位密码输入成为焦点。文字和数字采用实际可访问输入控件，即使门的美术资源没有加载也能操作。

标题：

> 最后一份礼物

已完成谜题时：

> 路刚开始的时候，你已经找到打开它的办法。

当前设备未完成谜题时：

> 这里需要四位密码。  
> 如果你已经记得，可以直接打开；也可以去信号花圃寻找线索。

输入说明「输入四位密码」，按钮「打开这扇门」。使用单个四位文本输入，可以视觉分成四格；支持数字键盘提示和完整粘贴。`0305` 正确，`305` 不是完整密码，不能因转成数字而丢失前导零。

错误时保留输入、不限制次数。已解题显示「还没有对上。可以打开密码卡，再看一眼」及「我的密码卡」；未解题显示「还没有对上。可以回到信号花圃，找到这四个数字」及「去找线索」。

新设备可以直接到礼物之门输入记得的 `0305`。这只设置 `giftUnlocked=true`，不伪造谜题完成、不取得密码卡。尚未解锁时直接请求门内礼物视图，必须转到礼物之门，不提前渲染礼物正文和生日解释。兼容入口 `#lock` 的映射由技术规格处理。

## 8. 门内的礼物

### 8.1 展示与节奏

门打开以后减少环境运动，让阅读与现场交流成为重点。不自动倒数、播放长旁白或跳走。

按以下顺序呈现：

1. 礼物图片；缺失时使用完整的中性礼物插画或明确占位；
2. 实际礼物名称；
3. 真实选择理由，为空则省略；
4. `0305` 的生日解释；
5. 连接现场的短话与返回音乐花圃的入口。

没有真实内容时，开发版本使用清楚的待填标记并列入交付清单。不能自动编出某款礼物、价格、“你一直想要它”等理由。正式收礼界面不要出现“请修改配置文件”之类开发说明。

### 8.2 通用文案

标题：

> 生日快乐。

说明：

> 有一份礼物，想当面交给你。

密码解释：

> 0305，是我的生日。  
> 我把它留在这里，作为这份礼物的署名。

连接现场：

> 接下来这部分，在屏幕外。

回访邀请：

> 想听音乐的时候，记得这里还有九首曲子。

入口「回到音乐花圃」和「回到花园」。具体署名、选择理由及语气由送礼者集中修改。

## 9. 回访、继续与现场展示

### 9.1 继续规则

- 无主线进度：显示「走进去看看」，可直接点歌。
- 谜题做了一部分：显示「继续旅程」，恢复尚未完成的卡片。
- 谜题完成、过场未看：可以继续密码卡与短过场，也可直接点歌。
- 谜题完成、过场已看、礼物未开：可继续到礼物之门，也保留点歌。
- 礼物已解锁：主要入口是「抽一首曲子」，次级入口「重看礼物」；仍可回到花园观看。

只抽过歌不代表开始或完成了谜题。直接开过礼物也不代表已解题。`scene`、相机位置、正在播放的动画是临时状态；刷新后的入口根据有效业务进度与合法直达链接确定。

v1 不制作独立重放或清空进度按钮。「回到花园」只改变视图，不删除业务进度，也不重抽歌曲。

### 9.2 现场节奏

进入、继续、抽取、开门都由人主动触发。邀请出现后可一直停留，曲目出现后可以聊天，礼物文字不会自行消失。页面中的声音开关始终明确，可选邀请语音不会自动覆盖现场讲话。

桌面主要验证完整构图和靠近过程；手机保留相同的核心内容、可见入口、清楚的谜题与结果卡。手机可减少远景层与复杂镜头运动，但不减少音乐可用性或改动随机规则。

## 10. 集中修改内容与素材

以根目录 `content.template.json` 为内容来源，保留原有 `site / people / puzzle / music / gift / theme` 分组，新增 `garden / assets`。

| 分组 | 送礼者主要修改什么 |
| --- | --- |
| `site` | 暂定标题、邀请、继续与点歌入口文案 |
| `people` | 收礼者称呼、送礼者署名；未知时保持空字符串 |
| `puzzle` | 题面与提示文案；固定算法数据不随意改动 |
| `garden` | 场景名称、靠近/返回提示、现场过渡文案 |
| `music.songs` | 九个固定编号对应的曲名和真实选择理由 |
| `gift` | 礼物名、理由、图片、祝福、生日解释 |
| `theme` | 颜色参数，与设计规格保持一致 |
| `assets` | 已实际准备的分层画面、关键物件和可选声音引用 |

未提供的素材使用 `null`，加载器应跳过并使用明确的本地替代呈现，不能请求不存在的示例路径。素材替代帮助继续开发与故障时使用；简单占位不构成 M1 美术样片的最终验收。

数字、按钮、题面、曲名、照片文字不嵌入生成背景图。九朵音乐花的装饰资源不改变 `music.songs` 的编号映射。素材准备的尺寸、透明层、制作提示和绑定清单见 `ASSET_BRIEF.md`。
