# A 方案：秘密花园视觉与验收规格

## 1. 已确定的方向

本版采用用户选定的 A 方案：**走进一座明亮、柔软、有手作感的秘密花园。** 首次在电脑上由两个人共同探索；以后收礼人可以用手机直接进入音乐花圃抽歌。谜题、随机规则、密码和内容边界以 `PRODUCT_SPEC.md` 为准，本文件规定它们怎样出现在同一个可探索世界里。

体验包含花园总览、信号花圃近景、音乐花圃近景、礼物门和门后礼物。邀请位于总览，`1001 → 9` 属于过场；场景标识统一为 `overview / puzzle / music / lock / gift`。总览与近景共享美术语言和空间线索，允许返回原花园，不做自由漫游游戏。

本次方案替换旧的象牙白窄页面、纸卡堆叠方案，也替换此前讨论过的写实夜景、黄铜温室方向。三张功能卡、全屏渐变加粒子、旋转星球都不是本版主画面。

## 2. 开发第一步：M1 可操作美术样片

**先完成能代表最终美术品质的一个小片段，再连接完整业务。** 样片的操作长度约 20—30 秒，可随时停下观看；这是设计范围，不是页面倒计时。

样片必须能完成：

1. 打开后看见完整花园，有前、中、远景和清楚的视觉焦点。
2. 移动指针时有小幅视差，触碰一处花叶或灯具有回应。
3. 点击信号花圃物件入口，视角靠近一个已经设计过的近景。
4. 看到可读的演示标题和一个真实可点击控件；演示不提前显示密码。
5. 点击“回到花园”，回到原总览，焦点返回原入口。

M1 不要求把三关业务先做完。灰盒可用于调试位置，但验收样片必须换成有统一形状、配色和质感的美术素材。若素材缺失，应明确列出缺失项与替换位置，标记为结构样片，不能声称视觉已完成。

新项目默认使用 React + TypeScript + Vite，R3F / Three.js 构建有限的 2.5D 分层舞台，GSAP 管理短转场，HTML/CSS 承担真实文字与控件。素材可以是分层插画，不要求完整建模或先学习 Blender。已有项目沿用现有栈；具体依赖与动画职责以技术规格为准。纯 DOM/CSS 版本作为图形不可用和减少动态效果的退化路径。

## 3. 美术基准

| 项目 | 执行方向 |
| --- | --- |
| 场景 | 明亮花园、圆润草丘、弯曲小路，有空气与前后层次 |
| 主体绿色 | 鲜活苔藓绿 `#6E934B`，深色植物与阴影 `#385B41` |
| 天空 | 淡蓝 `#D8ECF2`，云与纸签为奶油白 `#FFF8E8` |
| 花与主角物件 | 花瓣粉 `#E8A8BC`，少量浅紫 `#C7B8E3` |
| 灯光 | 暖浅黄 `#F3D98B`，小范围柔和光晕，数字仍清楚 |
| 正文 | 深绿黑 `#253B32`，次级文字 `#526657`，放在近乎不透明的浅色阅读底上 |
| 材质 | 草丘柔软有细节；主角物件有简洁软高光；手绘花叶与立体物件保持同一光向 |
| 形状 | 有机曲线、略带不规则的轮廓；九朵花保持同一家族而非九个完全相同球体 |
| 字体 | 正文使用清楚中文字体；手写气息用于短标题/注释；二进制与密码用等宽数字 |
| 个人细节 | 真实署名、邀请、可选语音和少量私人小物件；没有资料时省略，不虚构 |

色值是第一轮制作基准，最终须随素材统一校色。不要在不同来源图片上叠加互不一致的滤镜；透明边框、模糊和粒子也不能掩盖素材风格不一致。

## 4. 总览构图与空间层级

### 桌面主构图

以 1440×900 为主要制作参考，同时检查 1366×768 和 1920×1080。场景充满视口，标题与主角物件保留在中央安全区域；全站不受 720px 窄阅读列限制。近景操作面板可以设适合阅读的最大宽度。

| 层级 | 内容 | 构图职责 |
| --- | --- | --- |
| 远景 | 天空、两三团云、低对比远丘 | 留出空气和标题位置，避免纹理抢正文 |
| 中景环境 | 草丘、弯曲小路、少量花丛 | 联系三处目的地，暗示继续靠近的方向 |
| 中景主角 | 信号灯、音乐花圃、礼物小门 | 有清楚轮廓与留白，承担导航 |
| 前景 | 左下或右下的花叶、少量枝条 | 遮挡局部边缘，形成走进场景的感觉，不覆盖控件 |
| 交互层 | 入口标签、阅读面板、按钮、输入 | 使用 DOM，随场景锚点定位，但不随风摆动、倾斜或失焦 |

建议视线从较近的左中信号灯进入，顺小路看到中部音乐花圃，最后在偏右稍远处看到奶油色小门。三处轮廓可出现在同一个全景中，初次打开时不展开全部说明。

总览可以出现远处花圃剪影，但第一屏不直接写出“九首”、`1001`、`0305` 或生日含义。进入音乐区域或通过 `1001 → 9` 转场后，再完整展示九朵花。

### 手机构图

手机保留同一世界的颜色、形状和物件，用竖屏构图或重排锚点适配，不把桌面整幅图缩成小字画。景物可减少，操作与文字保持正常字号。手机重点照顾进入音乐花圃、查看结果、复制文字，三关仍须完整可完成。

触控范围以至少 44×44px 为项目目标。320px 宽度下不能横向溢出。曲目长标题自然换行；锁输入与键盘弹出时不能被固定底栏遮挡。

## 5. 场景和交互形态

### 5.1 花园入口与总览

标题暂用“留给你的一小片世界”，一两行邀请放在纸签旁。“走进去看看”可以依附在枝头纸签或小径入口上，同时保留清楚的文字与按钮语义。

加载完成后保留安静的停留状态，由用户开始。显示真实资源加载状态，不为仪式感伪造漫长进度。总览始终有可见但低调的“我来点歌”文字入口；物件入口和文字入口触发相同导航。回访时点歌可成为主动作。

### 5.2 信号花圃近景

一块平缓台面或草间浅色阅读区承载解码片、当前信号卡、四盏输出灯。环境保留花叶与光线，操作背景保持清楚。

解码片、信号卡、我的结果三行严格按四列对齐，数字为实时文字。灯外壳可以是独立图片或简单 3D 物件，控件与标签使用 DOM。每格初始未选择，`0` 与 `1` 都有清楚选项；不要为了像花园而把四格分散在不同远近的位置。

每次只集中展示 A 或 B 一段。先逐位比较，再显示 `8、4、2、1` 位权及十进制输入。提示在固定位置，错误保留输入，成功后小灯稳定点亮。两段完成才得到密码卡。

### 5.3 密码卡与音乐转场

`03` 与 `05` 按顺序拼成 `0305`，收为可再次查看的道具。此时不解释生日。随后用同一张解码片展示 `1001 → 8 + 1 → 9`，音乐花圃进入近景。

这是一段揭示，不增加新题目。用户可直接继续；减少动态效果时显示相同静态信息。数字含义不能依靠看完整动画才能读到。

### 5.4 音乐花圃近景

九朵花分布在弯曲花圃中，有高低与前后层次，不做整齐的 3×3 功能卡片。各花稳定对应固定编号与曲目，外观差异控制在同一套形状语言里。

“让花园替你选一首”是唯一产生随机结果的主动作，可附在一颗种子旁，并有清楚的 DOM 按钮。触碰某朵花只做轻微回应，不让人误以为是在随机抽取。

一次抽取先确定结果，再让种子飘向已选花朵。花展开或发亮，出现曲目卡。重复抽到同一朵仍有新的事件反馈，花不消失、不耗尽。结果卡有稳定浅色背景，包含两位编号、曲名、可选真实理由、邀请与复制动作。

“先去看礼物”和“回到花园”清楚可达，不要求先抽歌。手机上的结果卡应方便截图。

### 5.5 礼物之门与揭晓

奶油色门扇配少量粉色缎带或植物边框，轮廓轻巧。锁近景使用一个支持完整粘贴的四位文本输入；视觉可分四格，不能丢前导零。

输入正确密码，小门打开，出现清楚的礼物阅读区。按产品规格呈现礼物、真实理由、`0305` 的生日含义和点歌入口。礼物照片单独加载，不画进背景。

揭晓时减少环境动态，给现场交流和取出实物留下空间。内容可停留，不自动结束或切回总览。

## 6. 呼吸、回应和过渡

以下是首轮调试起点，应根据实际设备体验调整。

| 类型 | 建议行为 | 节奏与约束 |
| --- | --- | --- |
| 云 | 极慢横移 | 约 25—50 秒一段，自然循环 |
| 植物 | 同一阵风，局部略有相位差 | 约 6—12 秒往复，小幅度、根部稳定 |
| 纸签 | 偶尔轻晃 | 低频，阅读时文字稳定 |
| 灯 | 小范围呼吸亮度 | 约 5—8 秒，不闪烁、不满屏光晕 |
| 指针视差 | 远景少、前景稍多 | 先从约 6—24px 的屏幕偏移调试；关键按钮命中区不逃离指针 |
| 触碰 | 抬起、弯动或微亮选其一 | 约 150—300ms 回应 |
| 总览与近景 | 沿一致方向靠近或返回 | 约 0.8—1.4 秒；无持续自动运镜、镜头滚转 |
| 抽歌 | 种子到达选中花，结果展开 | 约 1—1.6 秒，中断时仍保留同一结果 |
| 开门 | 门扇或前景打开 | 约 0.8—1.2 秒，之后保持阅读状态 |

业务状态独立于动画生命周期。动画不是解谜成功、保存结果或解锁礼物的唯一触发器。转场期间防重复导航，完成或取消后恢复交互；减少动态效果时直接切换或短淡入。

可选短音效仅在用户主动开启声音后播放，开关位置稳定。M1 与首版闭环不要求已有音源；无音频时省略入口，不放无效播放按钮。

## 7. 可访问性与退化体验

- 所有主要交互有 DOM 语义、可见焦点和键盘路径，不依赖悬停、精细拖拽或单纯颜色。
- 物件热点有文字名称；装饰层不抢焦点、不挡指针。视觉物件与按钮命中区一起定位。
- 进入近景后焦点移到标题或主要区域；返回时回到原入口。帮助弹层关闭后回到触发按钮。
- 输入、曲目和正文不烘焙在图片中，不随植物摇晃。小屏近景允许正常滚动。
- `prefers-reduced-motion` 下关闭环境循环、视差和长位移，保留静态层次与短反馈，业务照常工作。
- 低性能时降低装饰数量、景深、粒子和渲染分辨率。图形不可用时用静态分层场景与 DOM 完成相同流程。
- 资源失败或退化提示简短；收礼流程不出现技术堆栈、存储键或错误堆栈。

## 10. 正式赠送前的现场检查

用实际展示电脑走一次完整流程，确认窗口尺寸、字体、图片与音量；手机检查直接点歌、长曲名与手动复制。关键素材随应用提供，展示前确认加载完成。

首次体验可按五到八分钟设计，但页面不计时。讨论谜题或曲子时，世界保持安静可看。礼物揭晓后停留，给线下交付留下时间。

美术资产清单详见 `ASSET_BRIEF.md`，完整开发阶段以 `DEVELOPMENT_PLAN.md` 为准。
