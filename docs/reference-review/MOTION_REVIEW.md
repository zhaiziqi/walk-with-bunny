# 参考视频动作复核 · 2026-10-30

本次用户纠正：要像参考视频一样可以来回拖拽，不接受“只能横向”或“沿固定小路纵向推进、横向仅有限探看”的解释。当前网页的单一路线相机仍不符合此要求。旧 DEPTH_QA 检查的是该实现是否按自身设定工作，不能作为符合参考交互的验收结论。

## 本次实际查看方式

- 两段原始视频在本地浏览器从0开始播放到末尾，分别59.10秒、153.53秒；无声音分析。
- 对两段全时段按约2秒间隔取样，检查完整场景顺序。
- 第二段12–20、34–42、70–80秒另按约0.5秒间隔取样，核对连续运动与进入/退出的区别。
- 原始媒体未修改；查看页、抽样画面保存在motion-review/，不进入public或dist。抽样标签为近似时间，不声称每个视频帧均已人工查看。

## 可观察到的动作

- 第二段约12–18秒：标题花园转向溪流/about区域；随后有局部观察和环境运动。
- 约20–36秒：灯所在草坪、画架内容、返回草坪之间往返。
- 约34–40秒：从草坪内容返回草坪，再回到溪流，继续移向粉色布帘区域。
- 约42–46秒：布帘内部物件可在画面中横向来回改变位置；点入内容和退出是另一种转场。
- 约70–76秒：退出内容到布帘总览，再回到布帘外部，进入门和云所在区域。
- 约88秒后重复较长的一轮探索，确认这些是反复进入/返回的交互，不只是单向展示。

录屏没有完整显示鼠标按下/抬起、触控手指或输入事件。画面能证明多方向的观察、场景往返和内容进入/返回，但不能仅凭录屏断言原站的底层是平面拖动、相机环绕或某种库，也不能把每一次转场都判定为拖动触发。

## 以用户此次纠正为准的实现要求

- 按住场景后可在上下、左右及斜向连续拖拽，两个方向都是实际探索空间，不以一个progress值锁定路线。
- 可以随时换向、原路拖回和停留；边界只限制场景范围，不把用户吸附到一条小路。
- 近、中、远物件保持一致空间关系及层次，不把整个花园当作一张平面壁纸搬动。
- 点击物件靠近/打开内容与浏览拖拽独立；退出恢复进入前的完整二维位置及视角。
- 当前的底部“入口到信号花圃”单进度条不应继续作为主导航模型。
