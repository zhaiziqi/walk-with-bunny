## 替换一首曲目

保持已有 `id` 不变，只替换对应标题和可选理由。收到真实标题后，将这首的 `placeholder` 改成 `false`。九首必须保持完整且唯一的 1–9；不增删、重排编号或把重复抽取改为排除已抽中的曲目。

理由为空时用 `"reason": ""`。不要为填满曲目卡写占位故事。只有真实标题已填好才关闭该首的占位标记；其中任何一首仍待填，音乐页就继续保留预览提示。

## 替换礼物与照片

当前 `gift.items[]` 固定为 `passport-holder` 与 `sleep-mask`，点击小兔纸签后显示两件物品的名称，再点可盖回；未展开时读屏文字同样不泄露名称，没有 `Any guesses?` 可见提示。`gift.name` 保留组合名称作为配置概述。礼物页以拆开包裹后的两件物品呈现，`reason` 保持空字符串，`imageSrc` 保持 null；不因可选理由和照片暂缺而重新显示“礼物名称待填”。后续只接入用户补充的真实说明和图片，不把插画当成真实商品素材。

`gift.codeMeaning` 仍保留在配置中，但当前界面不渲染它，也没有旧的 `A small signature` 日期折叠说明。生日标题为 `Happy birthday.`。锁旁信封只读取实际完成的四题数字，不自动填入密码、不标记收纳、不改变礼物或曲目进度。已完成但未收信封时显示纸条；未完成四题不能由礼物解锁状态获得纸条。首次需提交正确密码后揭晓；已开过的入口先显示已开说明，可 `Open again` 或 `Try the code again`，不会清除成果。

若用户提供照片：

1. 从原文件制作适合网页的副本，先去掉不希望分享的内容，保留原文件在开发资料位置。
2. 仅将实际准备展示的照片副本放在 `public/assets/gift/` 等明确目录，再填写以 `/assets/` 开头的真实路径。例如文件确实已保存为 `public/assets/gift/gift-photo.webp` 时才填写 `/assets/gift/gift-photo.webp`。
3. 给 `gift.imageAlt` 写简短、准确的英文说明；实际预览检查照片比例、清晰度与阅读高度。
4. 没有文件时保持 `imageSrc: null`，不填一个猜测路径。当前默认水粉插画或用户照片加载失败时使用线描替代，名字仍需翻纸签查看；替代图不能代替真实素材验收。

放进 `public/` 的文件会被 Vite 复制到生产产物；不要把原相册、参考视频、身份证明、聊天截图、访问令牌或其他不准备向访问者展示的文件放进该目录。私人原件和开发参考继续放在不参与发布的资料位置。

## 当前谜题与固定产品规则

2026-11-02 用户补回的四道计算机知识题是当前依据，覆盖原交接 v2 的两组 XOR 设计。原始交接文件继续保留，不修改它来更新网页。详细题面和流程见 [FOUR_QUESTION_PUZZLE.md](FOUR_QUESTION_PUZZLE.md)。

- `puzzle.kind` 为 `computer-knowledge-v1`，四题 ID 按 `python / tcp / xor / binary` 排列，分别接受单个数字 `0 / 3 / 0 / 5`。`puzzle.code` 仍是字符串 `0305`。
- 题面、按需提示和答后解释集中在 `puzzle.questions[]`；修改措辞不能更换题目知识点、顺序或答案。TCP 英文用“握手的步骤数”，避免误解成三次独立握手。
- 每题答对的一位留在纸条上，四位齐后主动收进小信封，稍后用于礼物锁；没有旧解码片、A/B 信号或 `1001 → 9` 音乐过场。
- 当前不显示生日日期解释；不能提前将密码含义写入首屏、锁页提示或图片替代文字。
- 曲目是九首独立等权、有放回抽取；重复合法。曲目卡复制的是待用户自行发送的文字，不代表已经发送消息。
- 新设备知道密码可直接打开礼盒，不因此获得四题完成或小信封。
- 不增加自动播放、倒计时、自动跳走、兑换次数或付费规则。
